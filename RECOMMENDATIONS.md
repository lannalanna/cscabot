# Рекомендации по улучшению CSCA Math Bot

Уже реализовано: пути через `DATA_DIR`, БД (SQLite, пользователи и прогресс), `/stats`, кнопка «Продолжить», меню второго уровня (тема → подтема → задачи), поле `subtopic` в данных, проверка ответов (`check_answers.py`).

Ниже — что имеет смысл сделать дальше.

---

## Безопасность и надёжность

**1. Токен только из окружения**  
Сейчас в коде остаётся запасной токен. Лучше: `API_TOKEN = os.environ.get("BOT_TOKEN")` и при старте проверять, что он задан; иначе выходить с сообщением. В репозитории не хранить токены, добавить `.env` в `.gitignore`, описать переменные в README или в `.env.example`.

**2. Обработка ошибок в хендлерах**  
В callback'ах при обращении к `kapibara`, `topics`, индексам оборачивать в `try/except` (KeyError, IndexError). При ошибке — логировать и отправить короткое сообщение «Что-то пошло не так. Начните с /start» и показать главное меню.

**3. Валидация данных при загрузке**  
При чтении JSON проверять наличие полей `topic`, `options`, `answer` и что `answer` входит в A–E. При невалидной записи — логировать и пропускать её или падать с понятным сообщением.

---

## Код и структура

**4. Разделение на модули**  
Вынести в отдельные файлы: конфиг (пути, `topic_links`, константы), загрузку данных, клавиатуры, обработчики (команды, callback'ы). Так проще тестировать и добавлять новые команды/темы.

**5. Короткие callback_data**  
Использовать индексы тем/подтем в callback (например `t_0`, `s_0_1`), а не длинные названия, чтобы не упираться в лимит 64 байта при больших номерах вопросов.

**6. Версии зависимостей**  
В `requirements.txt` зафиксировать версии (например `aiogram>=3.0,<4`, `aiosqlite>=0.19`). Добавить `.env.example` с полями `BOT_TOKEN`, `BOT_DATA_DIR`.

---

## Удобство для пользователя

**7. Команда /help**  
Краткое описание бота, список тем, ссылки на канал/чат и при необходимости подсказка по инвайт-ссылке.

**8. Локализация**  
Вынести все строки (приветствие, кнопки, «Верно/Неверно», «Следующий вопрос», ошибки) в словари по языкам (например по `language_code` или выбор языка). Хранить в модуле или в `locales/ru.json`, `locales/en.json`.

**9. Повтор ошибок**  
Сохранять в БД вопросы, на которых пользователь ответил неверно. Добавить кнопку/команду «Повторить ошибки» по выбранной теме или по всем темам.

**10. Случайный порядок вопросов**  
Опция «перемешать вопросы» при выборе темы/подтемы (например `random.shuffle` для списка индексов в сессии).

---

## Новый функционал

**11. Режим «экзамен»**  
Режим: подряд N случайных вопросов по одной или нескольким темам без перехода в обсуждение. В конце — итог: X из N правильных. Опционально: лимит времени на тест или на один вопрос.

**12. Админ-команды**  
Список `admin_id` из конфига/env. Команды только для админов: сводка по пользователям (старты, ответы, ошибки по темам), рассылка сообщения всем пользователям из БД. По желанию — добавление/редактирование вопросов через бота.

**13. Избранное**  
Возможность «добавить в избранное» по вопросу и отдельный раздел «Избранные задачи» для повторения.

---

## Инфраструктура

**14. Docker**  
`Dockerfile`: установка зависимостей, копирование кода, запуск бота. Том для `data/`. В README описать `docker build`/`docker run` и переменные окружения.

**15. Тесты**  
Юнит-тесты: загрузка данных (JSON, обязательные поля), разбор callback_data. Интеграционный тест: диспетчер + мок Telegram API, отправка `/start` и callback'ов.

**16. Логирование**  
Настроить `logging` (формат, уровень, консоль/файл). Важные события (старт/стоп, загрузка данных, ошибки, ответы пользователей) логировать через `logging`. Файлы `res.txt`/`usr.txt` при необходимости оставить только для аналитики.
