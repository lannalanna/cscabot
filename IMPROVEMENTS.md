# Предложения по улучшению и развитию CSCA Math Bot

Ниже — приоритизированные идеи: от исправления багов и быстрых улучшений до масштабирования и новых фич.

---

## Критичные исправления

### 1. Ошибка в обработчике произвольных сообщений

**Проблема:** В конце файла обработчик `@router.message()` обращается к `kapibara[j]` (где `j=0`). `kapibara` — это словарь с ключами-названиями тем (`"sets"`, `"trigonometry"` и т.д.), а не числами. При любом текстовом сообщении будет `KeyError`.

**Исправление:** Брать первый вопрос из первой темы, например:

```python
first_topic = topics[0] if topics else None
k = kapibara[first_topic][0] if first_topic and kapibara.get(first_topic) else None
# и проверка на None перед отправкой
```

Либо всегда показывать только главное меню (без вопроса):

```python
await message.answer("...", reply_markup=start_kb())
```

---

### 2. Жёсткие пути к файлам

**Проблема:** Пути вида `/data/`, `/data/usr.txt`, `/data/images/` не работают на Windows и при запуске не из корня сервера.

**Исправление:** Ввести базовую директорию проекта и использовать её везде:

```python
import os
BASE_DIR = os.path.dirname(os.path.abspath(__file__))
DATA_DIR = os.environ.get("BOT_DATA_DIR", os.path.join(BASE_DIR, "data"))
# Далее: os.path.join(DATA_DIR, "usr.txt"), и т.д.
```

Создать папку `data` в репозитории (или отдельно на сервере), в README описать переменную окружения `BOT_DATA_DIR` для продакшена.

---

### 3. Безопасность: токен и секреты

**Проблема:** Токен бота захардкожен в коде; в репозитории видны два токена.

**Исправление:**

- Хранить токен в переменной окружения, например `BOT_TOKEN`.
- В коде: `API_TOKEN = os.environ.get("BOT_TOKEN")` и проверка при старте.
- Удалить токены из кода и при необходимости отозвать старые в BotFather.
- В `.gitignore` добавить `data/`, `*.env`, `.env`.

---

### 4. Загрузка данных при отсутствии файлов

**Проблема:** При отсутствии `/data/usr.txt`, `data.txt` или `data_physics.txt` бот падает при старте (или при первом обращении).

**Исправление:**

- Проверять существование файлов и директорий при старте.
- Использовать `try/except` при чтении JSON и открытии файлов.
- Логировать ошибки (см. раздел про логирование) и при отсутствии данных выводить понятное сообщение и не поднимать диспетчер или выходить с ненулевым кодом.

---

## Улучшения кода и архитектуры

### 5. Разделение на модули

Сейчас весь код в одном файле. Имеет смысл вынести:

- **config.py** — константы, пути, загрузка из `os.environ`.
- **data_loader.py** — загрузка и объединение вопросов из JSON/TXT, построение `topics` и `kapibara`.
- **keyboards.py** — функции `start_kb`, `inline_kb`, `inline_kb_next`, `inline_kb_explain`.
- **handlers/** — отдельные файлы для команд (`start`, `help`), callback'ов (`qst`, `next`, `explain`) и fallback-сообщений.
- **middleware** (опционально) — логирование, проверка подписки, лимиты.

Так проще тестировать и добавлять новые команды/темы.

---

### 6. Конфигурация через один файл

Вынести в конфиг (или в `config.py` из переменных окружения):

- Токен бота.
- Базовый путь к данным (`DATA_DIR`).
- Список файлов с вопросами (`data`, `data_jan`, `data_physics`).
- Ссылки на каналы/чаты (текущий `topic_links`).
- Текст приглашения и лимит «после N вопросов показать инвайт» (сейчас 7).

Тогда смена окружения (локально/сервер) и добавление новых тем будут без правок логики.

---

### 7. Логирование

**Сейчас:** Запись только в `res.txt` и `usr.txt`, модуль `logging` импортирован, но не настроен.

**Предложение:**

- Настроить `logging` (формат, уровень, вывод в консоль и при необходимости в файл).
- Все важные действия (старт/стоп бота, загрузка данных, ошибки, ответы пользователей) логировать через `logging`.
- Файлы `usr.txt` и `res.txt` оставить как «сырые» логи для аналитики, но не заменять ими нормальные логи приложения.

---

### 8. Дубликат ключа в topic_links

В словаре `topic_links` ключ `'hyperbola'` задан дважды. Второе вхождение перезаписывает первое. Оставить один ключ и одну ссылку; при необходимости разные подтемы оформить отдельно (например, через `subtopic` в данных).

---

### 9. Callback_data и длинные названия тем

В Telegram длина `callback_data` ограничена 64 байтами. Названия вроде `"logarithnic functions"` или `"complex numbers"` в строке вида `next_{topic}_{j}` могут приближаться к лимиту при больших `j`.

**Варианты:**

- Использовать короткие коды тем в callback (например, `s` = sets, `t` = trigonometry), а полное имя — только для отображения.
- Либо хранить в callback только индекс темы: `next_0_5` (тема 0, вопрос 5), темы в списке по порядку.

## Новый функционал

### 10. Команда /help

- Краткое описание бота и списка тем.
- Ссылки на канал и чат (из `topic_links` или конфига).
- При желании — подсказка по инвайт-ссылке.

---

### 11. Прогресс и статистика по пользователю

- Хранить для каждого пользователя: по какой теме на каком вопросе остановился, сколько правильных/неправильных.
- Реализация: простой вариант — JSON-файл по `user_id` в `data/`; дальше — SQLite (таблицы `users`, `progress`, `answers`).
- Команда типа `/stats`: «По теме X решено N из M, правильных K».
- Кнопка «Продолжить» в главном меню — переход к последнему незаконченному вопросу по выбранной теме.

---

### 12. Номер вопроса и конец темы

- В сообщении с вопросом добавлять текст вида: «Вопрос 3 из 20» (или «3 / 20»).
- В конце темы уже есть сообщение «Больше нет вопросов…» — можно дополнить предложением перейти в другую тему или посмотреть статистику (если появится п.11).

---

### 13. Повтор ошибок и избранное

- Сохранять для пользователя ID вопросов, на которых он ошибся (в БД или в JSON).
- Команда или кнопка «Повторить ошибки» — выдача только этих вопросов по выбранной теме (или по всем темам).
- Опционально: «Добавить в избранное» (callback по вопросу) и раздел «Избранные задачи».

---

### 14. Локализация (русский и др.)

- Сейчас приглашение уже зависит от `lang == "ru"`.
- Вынести все строки бота (приветствие, кнопки, «Верно/Неверно», «Следующий вопрос», сообщения об ошибках) в словари по языкам (например, по `message.from_user.language_code` или выбор языка в настройках).
- Хранить строки в отдельном модуле или JSON (например, `locales/ru.json`, `locales/en.json`).

---

### 15. Режим «экзамен» и таймер

- Режим: подряд N случайных вопросов по одной или нескольким темам без перехода в обсуждение до конца.
- По окончании — результат: X из N правильных.
- Опционально: лимит времени на весь тест или на один вопрос (с предупреждением за 10 секунд).

---

### 16. Случайный порядок вопросов

- При выборе темы перемешивать порядок вопросов (например, `random.shuffle`) для данной сессии пользователя, чтобы проходить тему в разном порядке при повторных заходах.

---

### 17. Админ-команды

- Отдельный список admin_id (из конфига или env).
- Команды только для админов:
  - `/stats` — сводка по всем пользователям (сколько стартов, ответов, ошибок по темам).
  - `/broadcast <text>` — рассылка сообщения всем, кто когда-либо писал боту (ID из `usr.txt` или из БД).
  - Опционально: добавление/удаление вопросов через бота (загрузка JSON или по одному вопросу).

---

### 18. База данных вместо части файлов

- Заменить хранение в `usr.txt` и `res.txt` на SQLite (или PostgreSQL при росте нагрузки).
- Таблицы: пользователи (id, username, language, invited_by, created_at), ответы (user_id, topic, question_index, answer_index, correct, created_at), прогресс (user_id, topic, last_question_index).
- Это даст основу для статистики, «продолжить», повторения ошибок и админ-отчётов.

---

## Инфраструктура и качество

### 19. Зависимости и окружение

- В `requirements.txt` зафиксировать версии, например: `aiogram>=3.0,<4`.
- Добавить в репозиторий пример `.env.example` с полями `BOT_TOKEN`, `BOT_DATA_DIR`, при необходимости `ADMIN_IDS`.

---

### 20. Запуск через Docker

- Написать `Dockerfile`: установка зависимостей, копирование кода, запуск `python testbot.py` (или главного модуля после рефакторинга).
- Монтировать том с `data/` и при необходимости с `images/`.
- В README описать: `docker build` и `docker run` с переменными окружения.

---

### 21. Тесты

- Юнит-тесты для загрузки данных (корректный JSON, наличие полей topic, options, answer).
- Тесты для разбора callback_data (правильное извлечение темы и индекса).
- Интеграционный тест: поднятие Bot + Dispatcher с моком Telegram API и отправка команды `/start` и callback'ов.

---

### 22. Обработка ошибок в хендлерах

- В callback-хендлерах оборачивать обращение к `kapibara[top][j]` в try/except (KeyError, IndexError).
- При ошибке — логировать и отправить пользователю короткое сообщение «Что-то пошло не так, начните с /start» и показать `start_kb()`.
